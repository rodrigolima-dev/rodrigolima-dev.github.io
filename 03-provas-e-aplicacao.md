# Provas e aplicação

## Como ler os status

- **Verificado no código:** arquivo público lido em um commit fixo; a afirmação está sustentada pelo conteúdo daquele arquivo.
- **Executado nesta auditoria:** comando seguro rodado localmente nesta leitura, sem produção, credencial ou mensagem externa.
- **Relatado pelo autor:** afirmação encontrada em README, documentação ou texto do próprio projeto; não foi repetida localmente nesta auditoria.
- **Limite:** o que a prova não permite afirmar.

Os links usam commits fixos para não depender do conteúdo futuro da branch main.

## Confirmações que mudariam o texto

1. Um teste de build ou deploy verificável da API Java/Spring Boot mudaria apenas a legenda de execução; não mudaria o fluxo do case.
2. Um repositório público de uma API Node.js authored by Rodrigo permitiria colocar Node.js em um card técnico; sem isso, a headline continua sendo a versão profissional pedida e os cards não fazem essa afirmação.
3. Uma execução documentada de Docker ou n8n em ambiente reproduzível permitiria trocar “relatado pelo autor” por “executado”; não autorizaria chamar a demo de produção.
4. Evidência pública de que o botão de WhatsApp registra pedido ou pagamento mudaria o limite da Orpheuswim; os arquivos atuais só provam abertura de uma mensagem.
5. Um documento público que delimite os arquivos autorais da Digital Product Sales Journey permitiria avaliá-la como case de contribuição; o ORIGIN atual não sustenta autoria integral.
